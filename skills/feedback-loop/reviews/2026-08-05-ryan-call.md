# PerDollar — next iteration backlog (post-Ryan, 5 Aug 2026)

## The honest read

Ryan did not buy the audit. He said so plainly: *"I don't yet see how the solution helps me solve that for a client... it's not clear to me that if I go to Antonio and say let's do this audit, that it will get us where we need to go."* He also thinks the underlying problem is overstated — inference cost is small relative to everything else in a business, and the real gap is that nobody ties AI spend to outcomes.

That is now **two independent technical buyers rejecting the current product shape**. Kai (ShopAgentic) had already built the calculator internally and told you the price *data* was the valuable part. Ryan says the calculator doesn't reach the decision that matters and the data should be fed to *agents*, not people.

When two sharp, unconnected prospects reject the form but validate the substrate, that is a pivot signal, not a polish signal.

**One moment deserves particular attention.** Your own demo undermined your pitch: at a $5,000 budget the tool showed 3.2 million bug fixes. Ryan's response — *"Nobody has 3.2 million bugs... it'll cost you more to have the meeting about the five grand than it will five grand"* — is the single most damaging thing that can happen in a demo. The product argued, on screen, that the problem it solves is trivial. That is fixable in an hour and must be fixed before the next call.

**What he handed you instead** is a better product, and he handed it over twice:

1. **Expose the dataset to the agent, not the human.** Devs default to the biggest model and manual governance is unpoliceable — *"that's just a pain in everybody's butt."* If the coding agent consults a decision endpoint before each task, governance happens with zero friction.
2. **Counterfactual ROI, built in.** When the router moves a task off the developer's default, you know both numbers: what it would have cost and what it did. No A/B test, no eval harness — *"now all of a sudden you've got this aggregate ROI that is built into the product."*

That second idea is the answer to his own objection. It converts PerDollar from *measuring* cost into *proving savings it caused*. And it reframes the business: not €490 audits, but a cheap, frictionless product across many teams — his own TAM point.

**The competitive caution:** Ramp already ships a free quality-aware router. Your wedge is what Ryan named — existing routers have no decisioning (*"there's no decisioning built into it"*), and vendor routers are biased toward their own cheap inference (*"you actually need a middleman to be the router, which you could be"*). Independent, verified, per-task decisioning is the defensible slice. Not routing plumbing.

## Backlog, sorted by leverage

Leverage = (does it validate or kill the pivot) × (does it unlock a named buyer) ÷ effort.

### Tier 1 — build this fortnight, then go back to Ryan

**B1 · Decision endpoint — `POST /api/route`** · effort S · **highest leverage**
Given a task type, a list of models the team actually has access to, and optional constraints (min capability, max latency), return the recommended model, the reason, expected cost, and the runner-up. The data and the ranking logic already exist in `app.html`; this exposes them as a machine-callable decision rather than a human-readable table.
*Hypothesis:* the dataset is more valuable consumed by agents than read by people.
*Test:* Ryan can curl it and immediately see what a coding agent would receive.

**B2 · Counterfactual savings ledger** · effort S/M
Every routing decision records: the caller's default model, the model recommended, actual tokens in/out, actual cost, and the cost the default would have incurred. Aggregate into "saved $X across N tasks this month." Ryan's exact mechanism, and the reason it works is that it needs no eval harness and no Jira integration to prove value.
*Hypothesis:* self-reported, auditable savings answer the "tie it to value" objection that killed the audit.
*Test:* after 100 routed tasks, does the aggregate number survive scrutiny from an engineering manager?

**B3 · Claude Code / MCP integration** · effort M
A skill or MCP server a developer installs so their agent consults B1 before starting a task, and reports to B2 after. This is literally the sentence Ryan said would be an easy sell: *"just plug this into half your team and we'll demonstrate that it's cheaper."*
*Hypothesis:* zero-friction adoption beats governance policy.
*Test:* one team, two weeks, a real savings number.

**B4 · Fix the trivialising demo** · effort XS · **do this today**
Default the app to a realistic team-scale scenario — e.g. a 30-developer team's monthly agentic-coding spend — so the headline reads in thousands of tasks and hundreds of dollars, not 3.2 million bug fixes. Consider showing monthly team cost as the primary figure and per-job cost as secondary.
*Hypothesis:* the absurd number is actively costing you credibility in every demo.
*Test:* does the next prospect argue the problem is too small?

### Tier 2 — small, fixes real defects Ryan surfaced

**B5 · Retire the word "quality"** · effort XS
He asked what it meant four separate times, because the slider says QUALITY and the column says CAPABILITY, and the answers given conflated capability with value. Rename the slider **MIN CAPABILITY** to match the column exactly, and let VALUE be the only blended metric. My previous rename caused this; it should be reverted.

**B6 · Make the task list visibly illustrative** · effort XS
Direct feedback: *"that wasn't immediately obvious to me... there's potential to elevate the message that here's an example of the analysis we can do."* Label the dropdown as example workloads and state that real task profiles come from the customer's own session metadata.

**B7 · State the scope boundary on screen** · effort XS
Ryan pushed hard on "how do you know the bug was fixed?" Your answer — you measure spend *toward* a task, not completion — is defensible but was never on the page. Put it in the assumptions block: this measures cost of attempts, not delivery of outcomes; completion lives in Jira and is out of scope.

### Tier 3 — deliberately deferred

**B8 · Task taxonomy from session metadata.** The hard problem underneath the audit. The router sidesteps it by deciding per request rather than per completed task — so this only matters if the audit business comes back.

**B9 · Eval-harness integration.** Ryan's "ideally I'd like to see this tied to an eval harness." Genuinely the holy grail, genuinely too big for now, and B2 gives you a credible value story without it.

**B10 · The €490 audit and its landing page.** Two prospects have now rejected it. Don't delete it — inbound may still convert — but stop building for it and stop leading with it.
